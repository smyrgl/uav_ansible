# Flight card: shakedown, 2026-10-05, flight 1

A flight card is the script of the flight, written before it and annotated
after it: which manoeuvres, in which order, for how long, and what each one
is for, so the bag and the ulog contain the measurements the roadmap stage
needs rather than whatever happened. One card per bag. The recorder's
post-flight step writes the measured half (`flight_card.md` beside the bag:
times, sizes, topic rates, gaps, sign-off); this half is the plan and the
pilot's notes.

## Before arming

- [ ] Site, usable radius and ceiling: <r> m / <h> m; fence set to match (`GF_MAX_HOR_DIST`, `GF_MAX_VER_DIST`, `RTL_RETURN_ALT` below the ceiling) or deliberately off.
- [ ] `SYS_HITL` 0; parameter set is the flight set (checksum: <...>).
- [ ] Health rows green on the GCS: GNSS fixed, Avia GPS sync, E1R streaming, PX4 / Guard "No write path".
- [ ] Recorder: ch 11 on before arming if the pre-arm seconds matter; otherwise it starts at arming.
- [ ] Pack: <n>, voltage <V>; wind <m/s>; light <...>.

## After landing

- [ ] Disarm; let the post-roll finish (30 s) before power-off.
- [ ] Download the ulog (QGC log download, or the automatic fetch once enabled).
- [ ] Back on the bench network: the bag offloads itself; replay and score on atomic.
- [ ] Notes: what deviated from the script, what the pilot saw, anything to repeat.

## Flown as a QGC mission

The manoeuvres above are also a mission: `2026-10-05-shakedown-1.plan`
(generated by `tools/make_mission.py` on the launch coordinate, legs 30 m
heading north; the item-to-manoeuvre table is in
`2026-10-05-shakedown-1.items.md`). Review it in QGC, drag the featureless
and mapped-ground passes onto the right ground, check the legs fit the yard,
upload. The FC's mission item changes are written into the bag's flight.json
by the recorder, so no marker switch is needed; the pilot supervises with a
hand on the mode switch.
